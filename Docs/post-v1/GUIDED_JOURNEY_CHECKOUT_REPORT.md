# GUIDED-JOURNEY-CHECKOUT — Execution & QA Report

**Baseline:** `ecc5009`  
**النطاق:** توجيه تجربة Prototype وخطوات Checkout محلية فقط؛ لا بوابة دفع أو بيانات بطاقة أو تحصيل حقيقي.

## مبدأ الرحلة المنفذ

أزيلت القرارات المبكرة والمتنافسة من نقطة بداية المنتج. المسار الآن يطلب من المستخدم إجراءً واحدًا واضحًا في كل مرحلة:

| المرحلة | ما يراه المستخدم | الإجراء الأساسي |
|---|---|---|
| 1. الاستخراج | أمثلة بحث قطاع/مدينة ورسالة «لا تقرر الباقة الآن» | ابدأ الاستخراج |
| 2. النتائج | بيانات Scraper وأعمدة Excel ونتائج مختارة | راجع النتائج |
| 3. الاختيار | Excel فقط أو CRM نمو مع فرق القيمة | اختر المسار |
| 4. التفعيل | باقة مرتبطة بالمسار، ثم Checkout تجريبي | اختر الباقة وابدأ الدفع التجريبي |
| 5. الإكمال | إيصال محلي وCTA واحد للوجهة التالية | تنزيل Excel أو إدارة الاشتراك/CRM |

تظهر باقة Scraper أو CRM فقط بعد أن يفهم العميل نتائج الاستخراج، ولا تظهر الأسعار كقرار سابق لأوانه في Landing. قرار CRM يذهب إلى Checkout التجريبي قبل أي تحويل إلى CRM، بينما يظل Excel مسارًا مستقلًا لا ينشئ Leads أو Deals.

## Checkout التجريبي الكامل

يبدأ اختيار باقة بديلة Checkout بأربع مراحل: بيانات الفاتورة، وسيلة الدفع المقنّعة، مراجعة الطلب، والإيصال. تتحقق الخطوة الأولى محليًا من اسم الجهة وبريد تجريبي صالح. تستخدم الخطوة الثانية مرجعًا بصريًا فقط `Visa •••• 4242` ولا تسمح بإدخال أو تعديل رقم بطاقة أو CVV. تعرض المراجعة السعر والضريبة العرضية والإجمالي، ثم تتيح نجاحًا تجريبيًا وفشلًا تجريبيًا واضحين.

عند النجاح، ينشئ النموذج Invoice بحالة `paid_mock` وBillingActivity محليين، ويحدث Subscription المحلي فقط. لا ينشئ العملية `RevenueEvent` أو `AttributionTouchpoint` ولا تصف نفسها كتحصيل حقيقي. يعرض الإيصال خيار تنزيل تجريبي أو وجهة تالية مفهومة، وتعيد حالة الفشل المستخدم إلى الفوترة بأمان.
