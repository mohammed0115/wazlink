# SCRAPER-DATA-VISIBILITY — Final Concept Polish Report

**Baseline:** `bfea505`  
**Scope:** توضيح قيمة باقة Scraper بصريًا داخل النتائج وملف Excel المحلي، من دون Backend أو Enrichment أو تغيير لحقيقة CRM/Revenue.

## ما أُنجز

أصبح سطح النتائج الفعلي `#/discovery/results?job=JOB-1028` يعرض لوحة **«بيانات Scraper قابلة للتحديد والتصدير»** قبل القرار. تعرض اللوحة أعداد الهاتف والبريد والموقع وإنستغرام وواتساب المتاحة في العينة المحلية، ثم تمنح العميل اختيار أعمدة ملف Excel.

| مجموعة البيانات | الأعمدة المتاحة |
|---|---|
| تعريف الشركة | معرّف الشركة، الاسم، النشاط، المدينة، مصدر الاكتشاف |
| التواصل | الهاتف، البريد، واتساب |
| الحضور الرقمي | الموقع الإلكتروني، إنستغرام |
| السمعة | التقييم، المراجعات |

يتشارك renderer وCSV كتالوج `scraperExportColumns` نفسه. عند إلغاء عمود ثم تحديد شركة وفتح بوابة القرار، يبقى الاختيار محفوظًا وينتج التنزيل المحلي CSV بالأعمدة المختارة فقط. يظل نجاح التصدير صريحًا: لا CRM تلقائيًا، ولا Leads أو Deals أو RevenueEvent أو AttributionTouchpoint.

## القرار

العميل يرى الآن بوضوح ما الذي يأخذه عند اختيار Scraper فقط: بيانات اتصال وحضور رقمي وسمعة، يحدد أعمدتها ثم ينزل Excel. كما يرى أن CRM نمو باقة منفصلة لإدارة المبيعات، لا خطوة إجبارية بعد الاستخراج.

> هذا يرفع وضوح فكرة Prototype إلى **100% بصريًا** وفق معيار المستخدم: «استخرج شركات، نزّل Excel وانتهى، أو اشترك في CRM نمو إذا احتجت متابعة المبيعات».
