# B7 — Security Threat Model

> **B7 status:** Target design only. Not closed. Awaits independent CTO verification.

| Threat | Attack | Impact | Mitigation | Acceptance evidence |
|---|---|---|---|---|
| Cross-workspace rule reference | a rule authored in workspace A references a Lead/Deal public ID belonging to workspace B | information disclosure or cross-tenant mutation | every reference resolved via Doctrine R-1/R-2 workspace-scoped lookup; a foreign-workspace reference resolves `404`, indistinguishable from absent (`B7_ENTITLEMENT_RBAC_TENANCY.md` §3) | `AT-TEN-1`, `AT-TEN-2`, `AT-TEN-3` |
| Forged trigger | a caller submits a synthetic event claiming to be `DealWon` without it actually happening | unauthorized action execution | B7 only consumes events from the frozen internal outbox/dispatcher pipeline — there is no public endpoint accepting an arbitrary event payload as a trigger (`B7_EVENT_CONSUMPTION_MODEL.md` §1); the only non-event trigger source in Phase 1, `manual`, goes through an authenticated, permissioned command (`RunAutomationNow`) | `AT-SEC-5`, `AT-TRIG-4` |
| Forged workspace | an event envelope's `workspace_id` is spoofed | cross-tenant execution | envelope `workspace_id` is populated by the producing domain's own trusted transaction, never by external input (`B7_EVENT_CONSUMPTION_MODEL.md` §2) | `AT-SEC-1`, `AT-TEN-4` |
| Arbitrary command injection | a rule DTO attempts to name an arbitrary command/table/SQL string | remote code execution / data corruption | closed DTO catalogs (`B7_API_DTO_CONTRACTS.md` §3) — no field can carry a command name, table name, or SQL fragment | `AT-SEC-3` |
| Arbitrary condition execution | a condition attempts to carry an expression/script | RCE | closed condition DSL, no `eval` (`B7_CONDITION_ENGINE.md` §1) | `AT-SEC-4` |
| SQL/code injection | any free-text field reaches a query unparameterized | data corruption | every B7 query is parameterized (standard ORM discipline, no dynamic SQL construction from rule content anywhere in this design) | `AT-SEC-3`, `AT-SEC-4` |
| Permission escalation | a `sales`-rank member crafts and activates a rule to perform an action their own role could never directly perform | unauthorized mutation | the target command's own RBAC check runs at invocation against the **authority principal** — `automation_rule_revisions.activated_by_membership_id`, read live under their current role (`B7_SYSTEM_ACTOR_AUTHORIZATION.md` §3.1, `B7_ACTION_AUTHORIZATION.md` §1 layer D). Automation can never do what the member who switched it on could not do themselves at that moment; no workspace-level permission exists to escalate through | `AT-SEC-9`, `AT-RBAC-6` |
| Authorization principal loss | the membership that activated a rule is removed, suspended, or downgraded, yet the rule keeps acting under its former grant | unauthorized mutation with no accountable human | layer D is evaluated against the authority principal's *current* role, read live and uncached at every invocation (`B7_SYSTEM_ACTOR_AUTHORIZATION.md` §3.1, §3.3); losing the principal blocks the action non-retryably (`B7-AF-022`) and mutates no rule state (§3.3a) | `AT-SEC-7`, `AT-SEC-8`, `AT-SEC-10`, `AT-SEC-11`, `AT-SEC-12` |
| `system:automation` superuser abuse | an implementation defect treats the automation actor as exempt from RBAC/entitlement/validation | unauthorized mutation across every domain | `B7_SYSTEM_ACTOR_AUTHORIZATION.md` §2's five structural facts — `system:automation` carries no grant of its own; every permission is borrowed live from the authority principal (§3.1) | `AT-SEC-2`, `AT-SEC-9` |
| Entitlement bypass | a workspace without `automation.rules`, or past its `automationRuns` limit, still gets executions | commercial policy violation | capability checked at admission and before every action invocation; one `automationRuns` unit reserved transactionally per run created (`B7_ENTITLEMENT_RBAC_TENANCY.md` §4-§4.1) | `AT-ENT-1`, `AT-ENT-2`, `AT-ENT-5`, `AT-ENT-6` |
| Automation loop DoS | an unbounded self-triggering cycle consumes workers/target-domain capacity | resource exhaustion, cascading failure into other domains | `B7_LOOP_PREVENTION.md` §1's three-layer bound | `AT-LOOP-1`, `AT-LOOP-2` |
| Retry storm | many actions retrying simultaneously overwhelm a target domain | target-domain degradation | frozen exponential-backoff-with-jitter (`BACKEND_RETRY_POLICY.md`), reused verbatim, plus the execution budget (`B7_RATE_COST_MODEL.md` §2) | `AT-RETRY-1` |
| Message spam | a rule configured to send many messages in a tight loop | provider cost, recipient harassment, reputational/regulatory risk | `send_message` is mandatory `approval_required` (§`B7_ACTION_CATALOG.md` §3) — no fully-autonomous send path exists at all; B5's own rate/consent admission applies identically on top | `AT-B5MSG-1` |
| Duplicate side effects | a retried/replayed action re-invokes its target command | duplicate Task/Message/Deal-move | stable, non-random idempotency keys (`B7_IDEMPOTENCY_MODEL.md` §2) | `AT-IDEM-2`, `AT-IDEM-3` |
| Replay abuse | an operator replays a dead-lettered run repeatedly to re-trigger side effects | duplicate mutation | resume-mode replay never re-invokes already-succeeded actions; each replay is its own new `RUN-*` with its own idempotency key, and the target command's own idempotency guard is the second line of defense (`B7_DEAD_LETTER_REPLAY.md` §2) | `AT-REPLAY-1` |
| Stale rule execution | a run executes against a rule definition an author believed was already changed | unexpected mutation | resolved *for* correctness, not against it — `B7_RULE_REVISION_MODEL.md` guarantees a run always executes against the exact revision it captured, and `B7_RULE_LIFECYCLE.md` §3 makes this an explicit, documented property rather than a bug | `AT-RVN-1` |
| Secret exposure | a condition/action payload leaks a provider credential or raw message body into an audit log | credential/PII leak | condition field allow-list structurally excludes secrets (`B7_CONDITION_ENGINE.md` §6); `B7_OBSERVABILITY_AUDIT.md` §1's never-logged rule forbids logging raw provider credentials or message bodies | `AT-SEC-4`, `AT-OBS-2` |
| Event poisoning | a malformed or malicious event payload crashes the admission consumer | denial of service for all rules in the workspace | envelope/schema verification at admission step 2 (`B7_TRIGGER_ADMISSION.md` §1) rejects malformed envelopes without processing further; per-rule error isolation (`B7_TRIGGER_ADMISSION.md` §3) prevents one rule's evaluation exception from blocking others | `AT-SEC-5` |
| Out-of-order event abuse | an attacker deliberately reorders/delays events to manipulate `event.*`-based conditions | incorrect action execution | `current.*` namespace exists precisely so a rule author can opt out of trusting event ordering (`B7_CONDITION_SNAPSHOT_SEMANTICS.md` §3); `event.*` conditions accept this as a known, documented tradeoff, not a silent vulnerability | `AT-SEC-6` |

Every threat row carries both a structural mitigation designed elsewhere in this pack and at least one acceptance test whose **defined** assertion actually proves that mitigation. `B7-FIX.1` rebuilt this mapping after an independent audit found three rows citing tests that assert something else (forged trigger and `system:automation` superuser abuse had their references swapped; cross-workspace reference pointed at the envelope-derivation control) and two rows citing no test at all. `THREAT_ROWS_WITHOUT_ACCEPTANCE_EVIDENCE = 0`.
