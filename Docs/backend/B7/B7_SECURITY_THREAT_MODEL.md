# B7 — Security Threat Model

> **B7 status:** Target design only. Not closed. Awaits independent CTO verification.

| Threat | Attack | Impact | Mitigation | Acceptance evidence |
|---|---|---|---|---|
| Cross-workspace rule reference | a rule authored in workspace A references a Lead/Deal public ID belonging to workspace B | information disclosure or cross-tenant mutation | every reference resolved via Doctrine R-1/R-2 workspace-scoped lookup; a foreign-workspace reference resolves `404` (`B7_ENTITLEMENT_RBAC_TENANCY.md` §3) | `AT-SEC-1` |
| Forged trigger | a caller submits a synthetic event claiming to be `DealWon` without it actually happening | unauthorized action execution | B7 only consumes events from the frozen internal outbox/dispatcher pipeline — there is no public endpoint accepting an arbitrary event payload as a trigger (`B7_EVENT_CONSUMPTION_MODEL.md` §1); `manual`/`scheduled` triggers go through authenticated, permissioned commands only | `AT-SEC-2` |
| Forged workspace | an event envelope's `workspace_id` is spoofed | cross-tenant execution | envelope `workspace_id` is populated by the producing domain's own trusted transaction, never by external input (`B7_EVENT_CONSUMPTION_MODEL.md` §2) | `AT-SEC-1` |
| Arbitrary command injection | a rule DTO attempts to name an arbitrary command/table/SQL string | remote code execution / data corruption | closed DTO catalogs (`B7_API_DTO_CONTRACTS.md` §3) — no field can carry a command name, table name, or SQL fragment | `AT-SEC-3` |
| Arbitrary condition execution | a condition attempts to carry an expression/script | RCE | closed condition DSL, no `eval` (`B7_CONDITION_ENGINE.md` §1) | `AT-SEC-4` |
| SQL/code injection | any free-text field reaches a query unparameterized | data corruption | every B7 query is parameterized (standard ORM discipline, no dynamic SQL construction from rule content anywhere in this design) | `AT-SEC-3` |
| Permission escalation | a `sales`-rank member crafts a rule to perform an action their own role could never directly perform | unauthorized mutation | the target command's own RBAC check runs regardless of who authored the rule (`B7_ACTION_AUTHORIZATION.md` §1 layer D) — authoring a rule never grants the author's-role-independent workspace automation capability more than the workspace itself is entitled to |
| `system:automation` superuser abuse | an implementation defect treats the automation actor as exempt from RBAC/entitlement/validation | unauthorized mutation across every domain | `B7_SYSTEM_ACTOR_AUTHORIZATION.md` §2's five structural facts | `AT-SEC-AUTOMATION-1` |
| Entitlement bypass | a workspace without `automation.rules` still gets executions | commercial policy violation | checked at admission and before every action invocation (`B7_ENTITLEMENT_RBAC_TENANCY.md` §4) | `AT-ENT-1` |
| Automation loop DoS | an unbounded self-triggering cycle consumes workers/target-domain capacity | resource exhaustion, cascading failure into other domains | `B7_LOOP_PREVENTION.md` §1's three-layer bound | `AT-LOOP-1`, `AT-LOOP-2` |
| Retry storm | many actions retrying simultaneously overwhelm a target domain | target-domain degradation | frozen exponential-backoff-with-jitter (`BACKEND_RETRY_POLICY.md`), reused verbatim, plus the execution budget (`B7_RATE_COST_MODEL.md` §2) | `AT-RETRY-1` |
| Schedule amplification | many rules scheduling wakeups at the identical instant | thundering herd on the sweep worker | wakeup sweep processes in bounded batches with `SKIP LOCKED` (`B7_SCHEDULE_DELAY_MODEL.md` §3) — a B12 implementation concern, bounded by design intent stated here | `AT-SCHED-1` |
| Message spam | a rule configured to send many messages in a tight loop | provider cost, recipient harassment, reputational/regulatory risk | `send_message` is mandatory `approval_required` (§`B7_ACTION_CATALOG.md` §3) — no fully-autonomous send path exists at all; B5's own rate/consent admission applies identically on top | `AT-B5MSG-1` |
| Duplicate side effects | a retried/replayed action re-invokes its target command | duplicate Task/Message/Deal-move | stable, non-random idempotency keys (`B7_IDEMPOTENCY_MODEL.md` §2) | `AT-IDEM-B7-2` |
| Replay abuse | an operator replays a dead-lettered run repeatedly to re-trigger side effects | duplicate mutation | resume-mode replay never re-invokes already-succeeded actions; each replay is its own new `RUN-*` with its own idempotency key, and the target command's own idempotency guard is the second line of defense (`B7_DEAD_LETTER_REPLAY.md` §2) | `AT-REPLAY-1` |
| Stale rule execution | a run executes against a rule definition an author believed was already changed | unexpected mutation | resolved *for* correctness, not against it — `B7_RULE_REVISION_MODEL.md` guarantees a run always executes against the exact revision it captured, and `B7_RULE_LIFECYCLE.md` §3 makes this an explicit, documented property rather than a bug | `AT-RVN-1` |
| Secret exposure | a condition/action payload leaks a provider credential or raw message body into an audit log | credential/PII leak | condition field allow-list structurally excludes secrets (`B7_CONDITION_ENGINE.md` §6); `B7_OBSERVABILITY_AUDIT.md` §3 forbids logging raw provider credentials |
| Event poisoning | a malformed or malicious event payload crashes the admission consumer | denial of service for all rules in the workspace | envelope/schema verification at admission step 2 (`B7_TRIGGER_ADMISSION.md` §1) rejects malformed envelopes without processing further; per-rule error isolation (`B7_TRIGGER_ADMISSION.md` §3) prevents one rule's evaluation exception from blocking others | `AT-SEC-5` |
| Out-of-order event abuse | an attacker deliberately reorders/delays events to manipulate `event.*`-based conditions | incorrect action execution | `current.*` namespace exists precisely so a rule author can opt out of trusting event ordering (`B7_CONDITION_SNAPSHOT_SEMANTICS.md` §3); `event.*` conditions accept this as a known, documented tradeoff, not a silent vulnerability | `AT-SEC-6` |

`CRITICAL_FINDINGS`/`MAJOR_FINDINGS` from this analysis: none — every threat above has a structural mitigation already designed elsewhere in this pack, cross-referenced rather than duplicated.
