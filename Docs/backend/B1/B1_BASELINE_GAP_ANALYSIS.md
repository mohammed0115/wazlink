## 3. Gap classification

**BASELINE_GAPS_FOUND = 15** (one per matrix row requiring a B1 decision; all 15 rows are marked YES, with Entitlements limited to its RBAC boundary).

The gaps fall into four kinds:

1. **Named-but-unspecified (10).** B0 names the concept (Membership, Invitation, Session, active-workspace resolution, authorization ordering, owner semantics, workspace lifecycle, tenant isolation doctrine, audit vocabulary, account lifecycle) but does not specify fields, states, or mechanism. B1 specifies them without contradiction.
2. **Contract-implied obligation (2).** `Session.workspace_ref` is a **required** response field on the frozen `POST /auth/login`, and `Workspace.role` is a **required** field on the frozen `GET /workspaces` item. Both force B1 to make active-workspace resolution and role projection deterministic.
3. **ADR-mandated but unrouted (1).** ADR-009 requires email verification and password reset; no route exists. B1 adds them as B1-additive operations.
4. **Missing identity for addressable resources (2).** Membership and Invitation have tables but no registered public-ID prefix, so no route can address them. B1 **proposes and reserves** `MEM-` and `WINV-` as target prefixes through the extension mechanism the registry itself defines. **B1 registers nothing**: `BACKEND_PUBLIC_ID_REGISTRY.md` is unmodified, and no implementation may mint either prefix until the controlled registry extension is executed (`B1-D-002`, `B1-D-003`, Class B).
