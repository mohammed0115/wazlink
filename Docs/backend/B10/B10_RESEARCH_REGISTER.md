## 2. `B10-X-OWNER-EXEMPTION` — business-supplied compliance context

**Claim:** the current WazLink platform-operating entity is exempt from the relevant ZATCA e-invoicing requirement.

**Status:** `BUSINESS_ASSERTED / NOT_INDEPENDENTLY_VERIFIED`. No document in this repository, and no official ZATCA source consulted during this authoring pass, independently confirms this entity's actual VAT-registration status, revenue threshold position, or ZATCA-recorded exemption. This claim originates entirely from the product owner's own statement (recorded in this authoring session's instructions) and is treated exactly as brief §45 requires: as current business-supplied compliance context, not as independently verified legal fact.

**Architecture consequence:** the current deployment **may** configure `zatca_applicability = not_applicable` only when an authorized administrator (`tax.applicability.manage`, Owner-only) explicitly records this determination through `SetTaxApplicability`, with a required `reason` and an optional `evidence_ref`, producing a fully audited `TaxApplicabilityChanged` event (`B10_TAX_APPLICABILITY_MODEL.md` §7). Until that governed action occurs, the seeded `TaxProfile` remains `unknown` (§`B10_TAX_APPLICABILITY_MODEL.md` §2) — this document does **not** pre-set the profile to `not_applicable` on the owner's behalf, because doing so from a design-time document rather than a governed, audited runtime action would be exactly the unverified-claim-as-fact pattern brief §3/§45 forbids.

**This document does not state:** "ZATCA confirms WazLink is exempt." It states only that an owner-level assertion exists, is recorded as such, and has a defined, audited path into the system if and when an authorized operator chooses to act on it.
