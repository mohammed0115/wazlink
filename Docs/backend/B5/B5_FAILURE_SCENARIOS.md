# B5 — Failure Scenario Catalog

> **B5 status:** Target design only. Each scenario names a deterministic outcome and the document that governs it — no scenario is left as "TBD."
>
> **B5-FIX.1 note:** the independent CTO audit found real coverage gaps against its required failure-mode list (malformed webhook, unknown binding, idempotency-key-reused-with-different-payload; baseline permission/entitlement denial distinct from mid-flight revocation; generic provider 5xx distinct from timeout; concurrent-vs-sequential duplicate webhook; generic permanent rejection beyond template/media) and two padding entries that were boundary-behavior clarifications rather than actual failure/recovery scenarios. This revision adds eight genuinely new scenarios (DF-036–DF-043), removes the two non-failure entries (their content already lives, undisturbed, in the documents they cited), and merges one duplicate into its sibling. `FAILURE_SCENARIO_COUNT` changed from 40 to 45 — the number reflects a real recount, not a preserved target.
