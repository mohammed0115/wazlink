# B13 — Security Principles

> Design only. Twenty-five production security controls, each with a threat, the authority/resource it protects, its enforcement layer, its failure behavior, its audit requirement, its observability requirement, and the acceptance control that proves it. Every control cites the frozen anchor (`B13_FROZEN_INPUT_INVENTORY.md`) it operationalizes rather than inventing new authority.

## 2. Cross-cutting doctrine

Three rules recur across all 25 controls and are stated once here rather than in every document:

1. **404 over 403 for tenant-scoping.** Every cross-workspace probe returns `404 ENTITY_NOT_FOUND`, never a status that would let a caller distinguish "exists in another tenant" from "does not exist" (`FI-B1-05`, `FI-B1-07`). B13 does not weaken this anywhere it appears in B1–B12, and extends it to every new B13-introduced surface (dead letters, reconciliation cases, platform operator views).
2. **Deny/fail closed on ambiguity for anything with financial or tenancy consequence; fail open only for optional-provider availability.** An unresolved webhook binding, an unknown provider outcome, and a misconfigured security-critical setting all fail closed (§25 above; `FI-B12-08`; `B10-D-A019`). A single optional provider being unreachable does not fail closed on the whole application (`FI-B0-12`, `/health/ready` doctrine) — see `B13_HEALTH_READINESS.md` §3 for the exact boundary.
3. **A control that cannot be tested is not a control.** Every row above names an acceptance-control ID; the full test procedures live in `B13_ACCEPTANCE_TESTS.md`, and `SECURITY_CONTROL_COUNT = 25` is mechanically the row count of §1, re-derived in `B13_VERIFICATION_MATRIX.md` §2.

## 3. What this document does not decide

Numeric thresholds (rate limits, retention windows, timeouts) are decided in their owning document (`B13_RATE_LIMIT_ABUSE_MODEL.md`, `B13_PRIVACY_DATA_MINIMIZATION.md`) and classified in `B13_DECISION_REGISTER.md`. This document fixes the **shape** of each control — threat, protected resource, enforcement point, failure behavior — which is architecturally stable regardless of the tuned value.
