# B13 — Failure Scenario Catalog

> Design only. Each scenario: trigger, risk, expected safe behavior, authority preserved, audit evidence, operator response, acceptance reference. IDs are `B13-F-##`.

| ID | Scenario | Trigger | Risk | Expected safe behavior | Authority preserved | Audit evidence | Operator response | Acceptance ref |
|---|---|---|---|---|---|---|---|---|
| `B13-F-01` | Stolen session | cookie exfiltrated via XSS/network capture | attacker acts as the victim until revoked | `HttpOnly`/`Secure` block script/plaintext capture; bounded by 24h absolute expiry regardless | session registry is the sole revocation authority | `auth.session_revoked` | user/operator revokes via `RevokeAllSessions` | `AT-B13SESS-3` |
| `B13-F-02` | Removed membership with active session | `RemoveMember` while the user is mid-session | expect immediate lockout or, worse, continued unintended access | session re-resolves to a remaining eligible workspace, or revokes if none remain | `sessions.active_workspace_id` re-validated every request | `session.workspace_reresolved`/`.revoked_no_workspace` | none — automatic | `AT-B13SESS-6` |
| `B13-F-03` | Forged `workspace_id` | client submits a foreign `workspace_id` in body/query/path | cross-tenant read/write | pipeline never reads a client-supplied workspace value; path segment validated against, not substituted for, active workspace | `sessions.active_workspace_id` is sole authority | `authz.workspace_path_mismatch` | none — request denied | `AT-B13TEN-2/3` |
| `B13-F-04` | IDOR attempt | authenticated caller requests a foreign-tenant object by guessed/enumerated ID | data disclosure | `404 ENTITY_NOT_FOUND`, byte-identical to a miss | Doctrine R-1 | `authz.object_not_in_scope` | none — request denied | `AT-B13TEN-1` |
| `B13-F-05` | Forged webhook | attacker POSTs to a webhook endpoint without a valid signature | fabricated domain effect | verification runs before any parse/enqueue; rejected with `401`, zero domain effect | per-provider HMAC (`FI-B12-02`) | `webhook.rejected` (audit) | monitor `webhook_verification_failed_total`; investigate if sustained | `AT-B13WH-1` |
| `B13-F-06` | Duplicate webhook | provider redelivers the same callback (Meta's ~36h retry) | duplicate domain effect | dedup on `(provider, dedup_key)`; harmless `200` acknowledgement | receipt uniqueness constraint | receipt marked `duplicate` | none — automatic | `AT-B13WH-5` |
| `B13-F-07` | Cross-tenant webhook poisoning | attacker attempts to claim another tenant's binding while signing with a different one | cross-tenant dedup-identity collision | `dedup_key` prefixed by the *verifying* binding; collision structurally impossible | `B12-D-A056` | n/a — structurally prevented | none | `AT-B13TEN-6` |
| `B13-F-08` | Leaked API credential | a provider credential is committed, logged, or otherwise exposed | attacker acts as WazLink toward the provider, or forges callbacks | rotation invalidates the prior reference immediately; `configured` boolean never confirms the leaked value's continued validity | `*_REF` indirection (`FI-B12-04`) | `provider_configuration.changed` | rotate at provider console + WazLind reference (`B13_RUNBOOKS.md` §15) | `AT-B13SEC-4` |
| `B13-F-09` | Stale worker | a worker's heartbeat lapses mid-task | duplicate or lost effect if resumed incorrectly | lease expires; a fresh claim (new `lease_token`) re-executes safely; the original never resumes | fencing token (`B12-D-A055`) | `worker_executions` state | none — automatic reaping | `AT-B13CEL-5` |
| `B13-F-10` | Redis loss | Redis instance crashes or is flushed | fear of data loss | zero durable domain data lost; only rate-limit acceleration and Celery broker state affected | PostgreSQL is sole durable authority (`FI-B0-16`) | n/a | provision fresh instance (`B13_RUNBOOKS.md` §2) | `AT-B13CEL-4` |
| `B13-F-11` | DB loss | PostgreSQL instance fails catastrophically | full data-loss risk | restore from backup + WAL replay to most recent point; Redis/Celery resume only after DB verified | backup/PITR (`B13_BACKUP_RESTORE.md`) | restore audit row | full DR procedure (`B13_RUNBOOKS.md` §18) | `AT-B13DR-1` |
| `B13-F-12` | Storage outage | file storage provider unreachable | uploads/downloads fail; risk of state ambiguity on a delete | `unknown` recorded, resolved via `stat_object` before any state change | write-before-call (`FI-B12-08`) | reconciliation case | wait for provider recovery, reconcile (`B13_RUNBOOKS.md` §14) | `AT-B13FILE-8` |
| `B13-F-13` | Payment unknown outcome | connection loss during Tap charge creation | duplicate charge or lost confirmation | never blindly retried; resolved via `retrieve_charge`; Tap's 3-attempt bound makes reconciliation the guarantee | write-before-call + reconciliation (`FI-B12-08`, `FI-B8-01`) | `P-1` reconciliation case | `ReconcilePayment` (`B13_RUNBOOKS.md` §13) | `AT-B13PAY-3` |
| `B13-F-14` | Malicious upload | attacker uploads a file crafted to exploit a downstream consumer | stored-XSS, path traversal, resource exhaustion | 10-gate validation rejects mismatched/disallowed types; deterministic keys eliminate traversal; downloads never render inline | `FI-B11-03`/`04` | `file.upload_failed`/`.quarantined` | none — rejected at gate; `QuarantineFile` for edge cases | `AT-B13FILE-1…3` |
| `B13-F-15` | Log redaction failure | a code change accidentally logs a secret/PII field | secret/PII exposure via logs | allow-list-at-write-time discipline should prevent this structurally; if it occurs, treated as a leaked-credential/PII incident | `FI-B12-01` §3, `B13_LOGGING_REDACTION.md` | secret-scanning finding | rotate affected credential; scrub logs where legally permitted (`B13_RUNBOOKS.md` §15) | `AT-B13LOG-1` |
| `B13-F-16` | Provider retry storm | a provider outage causes many simultaneous transient failures | thundering-herd retry amplifying the outage | exponential backoff with full jitter, capped (`FI-B0-21`) | frozen retry policy | `provider_request_attempts` outcome distribution | none — automatic backoff; escalate if the provider signals abuse | `AT-B13CEL-*` (queue isolation) |
| `B13-F-17` | Queue backlog | a slow/failing workload class backs up its queue | user-visible latency for unrelated work | queue isolation by workload class prevents cross-contamination (`FI-B12-10`) | `FI-B12-10` | `queue_delay_ms{queue}` | scale worker concurrency (`B13_RUNBOOKS.md` §4) | `AT-B13DEPLOY-4` (rolling-safe) |
| `B13-F-18` | Unauthorized replay | a caller without `platform.operations.replay` attempts a dead-letter replay | unauthorized re-execution of a provider effect | `403 PERMISSION_DENIED` before any replay logic runs | RBAC step 8 (`FI-B1-05`) | `authz.permission_denied` | none — denied | `AT-B13OPS-1` |
| `B13-F-19` | Unauthorized reconciliation | a non-Owner attempts to resolve a `billing`/`finance` reconciliation case | financial-record manipulation by insufficient privilege | requires Owner for financial-domain cases regardless of `platform.operations.replay` grant otherwise | `FI-B9-02` financial-audit limit | `authz.permission_denied` | none — denied | `AT-B13FIN-6` |
| `B13-F-20` | Cross-tenant file access | a caller attempts to download another workspace's file via a guessed public ID or a stale ticket | data disclosure | Doctrine R-1 + per-request re-authorization; ticket alone grants nothing | `FI-B11-02` | `file.download_denied` | none — denied | `AT-B13TEN-11` |
| `B13-F-21` | Dependency critical vulnerability | a Critical-severity CVE is disclosed in a dependency WazLink uses | exploitation risk | tracked, triaged, patched within the defined window or risk-accepted explicitly (`B13_SUPPLY_CHAIN_SECURITY.md` §4) | none — this is a process control, not a runtime authority | dependency-review log entry | patch or document risk-acceptance | `AT-B13DEP-2` |
| `B13-F-22` | Bad deployment | a release introduces a regression or an incompatible schema expectation | error spike, possible data corruption | rollback to prior release; rolling-deploy compatibility rule prevents dropped/duplicated async work (`B12-D-A049`) | `FI-B12-13` | deploy/rollback log | roll back first, diagnose second (`B13_RUNBOOKS.md` §17) | `AT-B13DR-3` |
| `B13-F-23` | Backup restore failure | a restore attempt fails integrity validation | false confidence in recoverability | restore testing (`B13_BACKUP_RESTORE.md` §5) catches this **before** a real disaster, not during one | monthly restore-test cadence | restore-test log | investigate backup pipeline; do not treat an untested backup as reliable | `AT-B13BAK-1` |
