# تقرير تنفيذ S6-FIX

**الحالة:** مكتملة تقنيًا.  
**النطاق:** إصلاح S6 فقط؛ لا S7، ولا Backend، ولا قاعدة بيانات، ولا تكاملات خارجية.

## الملخص التنفيذي

تعالج S6-FIX الفجوات التي ظهرت في مراجعة CTO لشحنة Pipeline + Deals. أصبحت Deal الآن تملك عقدًا تجاريًا موحدًا يتضمن `title` و`value` و`currency` و`probability` و`lastActivityAt` وتواريخ الإغلاق النهائية. بقي الحقلان السابقان `name` و`probabilityOverride` طبقة توافق داخلية فقط، ولا تقرأ الواجهات الجديدة إلا العقد والـselectors الموحدة.

> إغلاق الصفقة كرابحة أو خاسرة يبقى تغيرًا محليًا في CRM. لا ينشئ التنفيذ `RevenueEvent` أو `AttributionTouchpoint` ولا يغير سلسلة إسناد S2.

| مجال الإصلاح | التنفيذ | النتيجة |
|---|---|---|
| عقد Deal | تطبيع Fixtures القديمة وإضافة `title` و`probability` و`serviceId` و`lastActivityAt` و`wonAt` و`lostAt`. | العقد موحد ومتوافق مع البيانات السابقة. |
| سياسة الاحتمال | احتمال المرحلة هو الافتراضي؛ override اليدوي يبقى حتى reset صريح. | انتقال المرحلة لا يغير override يدويًا. |
| Won/Lost | الرابحة تضبط 100 و`wonAt`؛ الخاسرة تضبط 0 و`lostAt` وسببًا إلزاميًا. | الحالات النهائية محمية ولا يعاد فتحها في Prototype. |
| Activity Audit | أحداث قيمة واحتمال ومرحلة وتاريخ إغلاق وعنوان ومالك وخدمة مع بيانات مقارنة. | كل mutation فعلي يحدّث `lastActivityAt`. |
| تعدد الصفقات | السماح لعدة صفقات مفتوحة للـLead عند اختلاف الخدمة أو العنوان المطبع. | يمنع التكرار النشط المطابق فقط. |
| Pipeline | selector واحد للقيمة المفتوحة والقيمة المرجحة في S6 وDashboard. | لا يوجد تعريف مالي ثانٍ للقيمة المفتوحة. |
| Kanban | سحب وإفلات إلى المراحل المفتوحة فقط، عبر `moveDealStage` نفسها. | أزرار النقل تبقى بديلًا قابلًا للاستخدام بلوحة المفاتيح. |
| قائمة الصفقات | بحث يشمل العنوان والشركة وLead والمعرّفات، مع فلاتر الإغلاق وTier ومصدر الاكتشاف وفرز القيمة المرجحة وآخر نشاط. | نتائج موحدة من مصدر Deals. |
| Deal 360 | عرض Confidence وGaps وServices وSales Approach من S4 بالمرجع فقط. | لا تنسخ الصفقة Score أو Intelligence. |

## الملفات المتأثرة

| الملف | الأثر |
|---|---|
| `client/js/data.js` | عقد Deal، lifecycle، validators، audit events، selectors الموحدة، واتساق Dashboard. |
| `client/js/pipeline.js` | Kanban بالسحب والإفلات، الفلاتر والفرز، Deal 360، وواجهات النماذج. |
| `client/js/app.js` | رسائل S6 وربط Lead 360 مع الصفقات المتعددة. |
| `client/js/crm.js` | عرض عدة صفقات مفتوحة من Lead 360 وفتح الصفقة الصحيحة أو إنشاء صفقة مختلفة. |
| `client/js/dashboard.js` | فصل الإيراد المعترف به عن Pipeline المفتوحة والمرجحة. |
| `client/css/s6.css` | حالات السحب والإسقاط والصفقات المتعددة على Desktop والجوال. |
| `ENTITY_MODEL.md` | توثيق عقد Deal وDealActivity وسياسة probability والحالات النهائية. |
| `scripts/verify-s6.mjs` | توسعة التحقق إلى بوابات CTO A–V. |

## حدود تبقى مقصودة

كل البيانات والتغيرات محلية في الذاكرة وتنتهي عند إعادة تحميل الجلسة. لا يوجد إرسال رسائل أو WhatsApp أو Inbox أو Automation أو Agent، ولا استخراج ويب أو API أو تشغيل خلفي. هذه الحدود مقصودة لأن S6-FIX لا يفتح S7.
