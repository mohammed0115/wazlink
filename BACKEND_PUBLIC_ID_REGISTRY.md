# WazLink Public-ID Prefix Registry

> **B0 status:** Documentation and contracts only. This registry is normative for B1 Foundation/API references and does not implement ID generation.

## Authority and invariants

Every externally visible persistent resource uses an immutable opaque `public_id` with a registered prefix. Internal UUIDv7 identity remains the primary identity and is never replaced by, or exposed only as, the public ID. Prefixes are case-sensitive. A canonical persistent identifier is unique globally unless the resource row below explicitly says that its database uniqueness is workspace-scoped; API lookups always require workspace authorization.

The generation rule is `public_id = <PREFIX>-<opaque immutable token>`. The token is generated by the canonical UUIDv7/public-ID service, is not derived from display names or sequential UI fixtures, and is stored once at creation. Collision handling is a transactionally retried unique-constraint failure; the service generates a new opaque token and never mutates an existing public ID. Public IDs are immutable after creation.

## C — deprecated or alias identifiers

| Prefix | Canonical replacement | Resolution |
|---|---|---|
| `TASK-` | `TSK-` | UI lookalike of the CRM Task resource; `TSK-*` is the canonical Task prefix |
| `AUTORUN-` | `RUN-` | `{id:"AUTORUN-1001", automationRuleId, ruleNameSnapshot, status}` is an AutomationRun; `RUN-*` is canonical |
| `AGA-` | `RUN-` | `{id:"AGA-8001", leadId, conversationId, type, status, requiresApproval}` is a governed agent action, which B0 models as an AutomationRun reached through `POST /automation/runs/{id}/approve`; `RUN-*` is canonical |

No C-class identifier is accepted as a new persistent public ID. Lookalike collisions are explicitly resolved: `TSK-` is Task and `TASK-` is its UI alias; `CONV-` is Conversation, `CON-` is Contact, and `COND-` is an automation condition fragment — all three are distinct and none may be substituted for another; `INV-` is a team-invitation fixture while `INV-BILL-` is the platform Invoice; `QRT-` is the Quick Reply Template messaging/UI fixture while `UPQ-` is the canonical persistent UpgradeQuote, and the two namespaces are disjoint and must never be substituted for one another; and `PIPE-` is the single canonical Pipeline prefix with no competing screen-fixture classification.

## Excluded non-identifier tokens

The reconstruction rule is mechanical and compound-aware: a token's prefix namespace is its **leading run of all-uppercase alphabetic segments**, and a token is an identifier only if at least one following segment is numeric. This yields `AGA-LOG-` from `AGA-LOG-8001` (never `LOG-`), `SIG-` from `SIG-1042-A`, `ACT-` from `ACT-1042-1`, and `INV-BILL-` from `INV-BILL-1001`. Runtime-generated namespaces are recovered from their generator call sites (`nextNumericId`/`s11Id`/`s11Audit`) as well as from literals, which is how `AUTOLOG-` and `AUTONOT-` are inventoried even though no literal of either appears in the frozen tree.

Applying that rule to `30bc15e9ca3c0205df2b49e792fce1b8e78a36b1` yields **55 identifier prefixes**, every one of which is classified exactly once in section A, B, or C above.

Every one of them is an all-alphabetic token with no numeric identifier segment, or is not uppercase-leading, and none is used as an entity `id` or reference field:

## Cross-domain invariants

`BUS-*`, `LEAD-*`, `CONV-*`, and `DEAL-*` are resolved by typed public-ID references and workspace authorization, never by display name. `DEAL-*` does not imply `REV-*`; a `REV-*` exists only after the explicit revenue-recognition command. `ATT-*` is attribution metadata, never recognized-revenue amount truth, and cannot mutate `REV-*`. `SUB-*`, `UPQ-*`, `INV-BILL-*`, `PAY-*`, and `TAX-*` are Platform Billing/Tax identities and are not customer CRM revenue identities. An `UPQ-*` UpgradeQuote is platform commercial authorization only; it never creates, implies, or mutates a `REV-*` RevenueEvent. Any new canonical prefix requires an ADR update, API/DTO update, index update, and traceability entry before implementation.
